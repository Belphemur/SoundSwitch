# Tools

> **Requires PowerShell 7+** (ships with Windows 11). The PowerShell scripts below are not compatible with Windows PowerShell 5.1.

- [`vswhere.exe`](https://github.com/Microsoft/vswhere) - Locate Visual Studio installations.
- [`markdown_to_html.py`](markdown_to_html.py) - Convert Markdown files to standalone HTML documents. Requires Python 3 with the `markdown` package (`pip install markdown`). Replaces the previously used `markdown-html` npm package.
- [`Publish-Release.ps1`](Publish-Release.ps1) - PowerShell 7+ script that orchestrates the full release workflow. By default it finds the latest draft release created by semantic-release using the GitHub CLI (`gh`), downloads the build artifact into `Final\`, delegates to Build-Installer.ps1 for installer compilation and code signing, uploads the signed installer (replacing existing assets with `--clobber`), sets the release body from the latest CHANGELOG.md entry (with optional user notes), and publishes after confirmation. With `-BuildFromSource` it builds from source instead (self-contained publishes that bundle the .NET Desktop Runtime, including HTML doc generation and asset bundling) and skips the publish steps. The `-InstallerReleaseState` is automatically derived from `-Channel` (beta → Beta, release → Release) unless explicitly overridden. The optional `-Architectures` parameter (`win-x64` and/or `win-arm64`, comma-separated, defaults to both) selects which arch payload is published and which installer(s) are compiled — nightly builds pass `win-x64` only.
- [`Install-BuildTools.ps1`](Install-BuildTools.ps1) - PowerShell 7+ script that uses winget to install GitHub CLI, Inno Setup 6, Certum SimplySign Desktop (cloud certificate provider for code signing), and Python 3 (with the markdown package), and obtains `signtool.exe` by downloading a lightweight standalone build from [Delphier/SignTool](https://github.com/Delphier/SignTool/releases) on GitHub (with a smoke test), falling back to the full Windows SDK via winget. Run once on a fresh Windows 11 machine.
- [`Sign-Binary.ps1`](Sign-Binary.ps1) - PowerShell 7+ script for code signing executables using signtool with SHA-256 digest and RFC 3161 timestamping (no SHA-1). Configurable certificate subject name (defaults to "OpenSource Developer, Antoine Aflalo"). Called automatically by Build-Installer.ps1 when signtool is available.
- [`Build-Installer.ps1`](Build-Installer.ps1) - PowerShell 7+ script focused on installer compilation and code signing. Takes a `-FinalDir` parameter (defaults to `.\Final`) pointing to a pre-populated directory with binaries, docs, and assets. Signs binaries and the installer using Sign-Binary.ps1, and invokes Inno Setup (ISCC.exe) directly, once per architecture via `-Architectures` (passing `/DTargetArch=x64|arm64`; defaults to both). Does not build from source, generate docs, or interact with GitHub releases — use Publish-Release.ps1 for the full workflow.
- [`upload_nightly_r2.py`](upload_nightly_r2.py) - Upload nightly build archives to Cloudflare R2 and notify Discord.
- [`Control-SoundSwitch.ps1`](Control-SoundSwitch.ps1) - PowerShell 7+ control surface for a live SoundSwitch instance, built on the same CLI/IPC and UI Automation primitives as the screenshot script. Launches or attaches to the app (`-Start`), sends CLI commands (`-Cli 'mute'`, `-Cli 'mute -t'`), selects Settings tabs (`-Tab Recording`), chooses the mute microphone through the real combo box (`-MuteTarget 'Windows default input'`), clicks buttons (`-Click`), captures windows (`-Screenshot`), lists windows (`-ListWindows`), reports state (`-Status`), and stops the instance it launched (`-Stop`). Dot-source it to drive the app interactively from a session. See the `mute-target-testing` skill.
- [`Test-MuteTarget.ps1`](Test-MuteTarget.ps1) - PowerShell 7+ runner for the microphone mute target feature's unit tests. Runs the focused fixtures by default, or the whole suite with `-All` and the COM audio tests with `-Audio`. Skips the flaky `RefreshDeviceTests.TestMultipleRefresh` (CI skips it too).
- [`Test-MuteTargetEndToEnd.ps1`](Test-MuteTargetEndToEnd.ps1) - PowerShell 7+ end-to-end test of the mute target feature. Backs up and restores `%APPDATA%\SoundSwitch\SoundSwitchConfiguration.json`, drives the real Settings UI and CLI, and asserts target persistence, mute-action targeting, default-input fallback, and the unavailable-device fallback that keeps the selection. Requires real microphones.
- [`Capture-DocumentationScreenshot.ps1`](Capture-DocumentationScreenshot.ps1) - PowerShell 7+ automation for the documentation screenshots. Builds the app and CLI, launches SoundSwitch, opens Settings through the CLI (`SoundSwitch.CLI.exe settings`), selects a settings tab with UI Automation, and captures the Settings window bounds with `PrintWindow` into `img\Documentation` (published on the website as `/images/`). Pass `-Click <control>` to click a button on the tab and capture the sub-dialog it opens, e.g. `-Tab "App Rules" -Click addAppSoundRuleButton` captures the "Add Rule" dialog. Use it to refresh the screenshots shown in the docs, e.g. `pwsh tools\Capture-DocumentationScreenshot.ps1 -Name Notifications -Tab Notifications`. See the `documentation-sync` skill for the full workflow.
